# eTL에서 요건 확인 (Chrome)

대상: `0.1.0-alpha.3`. 2026-10-25 한 학생 계정의 실제 eTL(`myetl.snu.ac.kr`, Canvas 기반)에서 로그인 판단, 대시보드, 과제 목록·상세, 공지 목록·상세, 첨부 다운로드, 모듈 화면을 읽기 전용으로 확인했다. 강좌마다 메뉴와 글이 다를 수 있으니 **화면에 보이는 것이 우선**이다.

목차: 1 허용과 금지 · 2 화면 구조 · 3 로그인과 과제 식별 · 4 과제 상세와 제출 기간 · 5 공지·모듈·첨부 · 6 판단 규칙 · 7 수집 범위와 실패 · 8 결론 직전 재확인

## 1. 허용과 금지

허용(읽기):
- 사용자의 실제 Chrome에서 페이지를 열고 글을 읽고, 보이는 링크를 따라가기
- 화면에서 본 강좌 ID로 같은 강좌의 표준 메뉴 주소(`/courses/<ID>/assignments`, `/announcements`, `/modules`, `/files`)를 바로 열기 — 같은 화면을 메뉴로 여는 것과 같다
- 요건이 걸린 첨부를 일반 다운로드로 받기(처음 받기 전에 이름·크기를 알리고 허락받음)

금지:
- 과제 제출·과제 다시 제출·업로드·파일 선택·저장·삭제 버튼, 제출 대화 상자, 양식 입력
- 로그인 정보 입력(자동 채움이 보여도), 쿠키·저장소·비밀번호 읽기
- 화면에 없는 주소 추측, `/api/v1/...` 같은 API 직접 호출, 숨은 데이터를 꺼내는 스크립트
- 성적, 쪽지, 다른 학생의 글·제출물, 식별과 무관한 화면
- 학생이 거부한 동작을 다른 탭·도구·메일로 다시 시도하기

이미 허락받은 범위(같은 eTL 세션의 읽기, 같은 과제의 다른 안내 첨부)는 다시 묻지 않는다.

## 2. 화면 구조 (관찰)

| 화면 | 주소 | 볼 것 |
|---|---|---|
| 대시보드 | `https://myetl.snu.ac.kr/` | 강좌 카드 "2026-2 <강좌명> (분반)"과 카드마다 "공지 - …", "과제 - …", "파일 - …" 링크(주소에 강좌 ID). 오른쪽 "할 일" 목록 |
| 과제 목록 | `/courses/<ID>/assignments` | 성적 그룹별 과제, "마감 9월 27일 오후 11:59"(연도 없음), 점수 |
| 과제 상세 | `/courses/<ID>/assignments/<과제ID>` | 제목, "마감 … 점수 … 제출물 유형 파일 업로드", 본문(없으면 "내용 없음"), 오른쪽 "제출물" 사이드바(제출됨·시각·파일명), "과제 제출"/"과제 다시 제출" 버튼 |
| 공지 목록 | `/courses/<ID>/announcements` | 처음엔 "공지로드"만 보임. 몇 초 뒤 다시 읽으면 항목마다 제목, 대상("모든 섹션" 또는 "1 섹션"), 본문 미리보기, "게시일시: 2026년 9월 3일 오후 4:48" |
| 공지 상세 | `/courses/<ID>/discussion_topics/<ID>` | 본문 전체와 첨부 링크(`/courses/<ID>/files/<파일ID>/download`) |
| 파일 | `/courses/<ID>/files/<파일ID>` | "Download <이름> (크기)". ZIP 등은 미리보기 없음 |
| 모듈 | `/courses/<ID>/modules` | 주차별 과제·강의자료·영상(외부 도구)과 주차 머리말 메모 |

알아 둘 것:
- 페이지 글 추출 도구는 본문 위주라 과제 상세의 "제출물" 사이드바를 빠뜨릴 수 있다. 요소 찾기·접근성 트리나 화면 확대로 읽는다.
- 과제 목록의 숨은 안내문("이 과제에 대한 제출물이 없습니다")은 상세 화면의 "제출됨" 기록과 다를 수 있었다. 제출 기록은 상세 사이드바로만 관찰한다.
- 영상·주차학습 같은 외부 도구(iframe) 안의 글은 읽히지 않을 수 있다. 요건이 거기 있을 수 있으면 읽지 못한 출처로 남긴다.
- 첨부는 Chrome 기본 다운로드 폴더(보통 `%USERPROFILE%\Downloads`)에 저장되고, 같은 이름이 있으면 `안내 (2).zip`처럼 번호가 붙는다. 방금 받은 파일(수정 시각이 가장 최근)을 쓰고 크기가 화면과 같은지 본다.

## 3. 로그인과 과제 식별

### 로그인
- **로그인됨**: 대시보드에 수강 강좌 카드가 보인다.
- **로그인 안 됨**: `nsso.snu.ac.kr/sso/usr/snu/mfa/login/view`, 제목 "로그인 - 서울대학교 2단계 인증". 학생에게 그 Chrome에서 직접 로그인해 달라고 하고, 끝났다고 하면 대시보드로 다시 확인한다.
- 연결된 Chrome이 여럿이면 학생이 로그인한 Chrome을 고르게 한다. 다른 프로필은 로그인되어 있지 않을 수 있다.
- 도중에 로그인 화면이 다시 나오면(세션 만료) 같은 방식으로 안내하고, 그동안 읽지 못한 출처는 미확인으로 둔다.

### 과제 식별
근거:
- 제출 파일의 제목·머리말·강의명·과제 번호·주제(`inspect` 출력)와 파일 이름
- 대시보드의 강좌명(영문 이름일 수 있음)과 분반, 과제 목록의 과제명·번호·주제
- 마감이 지금과 맞는지(참고만, 이것만으로 확정하지 않음)
- 학생이 말한 강좌·과제 이름(후보를 좁히는 근거)

한도(제품 탐색 범위이며 과제 요건이 아님): 후보 강좌 5개, 강좌마다 과제 목록 1화면, 과제 상세 합계 10개.

판단:
- 학생이 부르는 이름과 eTL 강좌명이 다를 수 있다(한국어 별칭 ↔ 영문 강좌명). 강좌명·주제·과제명을 함께 보고 대응을 밝힌다.
- 같은 강좌의 여러 분반(001, 002, 003)이 있으면 과제가 실제로 있는 분반, 학생이 말한 분반을 근거로 고른다.
- 하나로 좁혀지면 근거를 한 줄로 보여 주고 진행한다. 여럿이거나 없으면 판정하지 말고 후보와 근거를 보여 주며 한 가지만 묻는다. 여러 과제의 요건을 합치지 않는다.
- 살펴본 범위를 밝힌다(예: "강좌 3개, 과제 상세 4개를 봤습니다").

## 4. 과제 상세와 제출 기간

화면에 보이는 그대로 수집한다: 강좌·분반·과제명, 마감 원문, 점수, 제출물 유형, 허용 파일 형식(보이면), 본문 전체, 첨부·연결 문서, 사이드바의 제출 기록.

- 본문이 "내용 없음"이면 그 사실을 적고 공지·모듈·강의계획서에서 요건을 찾는다. 요건이 없다는 뜻이 아니다.
- 제출물 유형·허용 형식은 eTL 자체 제약이다. 교수자 지시와 다르면 둘 다 보여 준다.

제출 기간 상태:
- **열림**: 화면에 제출 가능 상태가 글로 보이거나, 시작·마감·현재 시각이 연도·시간대까지 확정되어 그 사이일 때만. 버튼이 보인다는 것, 마감이 미래라는 것만으로는 열림이 아니다.
- **마감 지남**: 마감 시각이 지났을 때. eTL 마감 표기에는 연도가 없으므로 강좌 학기(예: 2026-2)로 연도를 추정했다고 밝힌다. "과제 다시 제출" 버튼이 보여도 가능 기간이 글로 없으면 지금 제출 가능한지는 확인하지 않은 것이다.
- **알 수 없음**: 제출 버튼·가능 기간 표시가 없거나, 표기가 불완전할 때.
- 상태를 알려고 제출 버튼을 누르거나 제출 화면을 열지 않는다. 화면의 "제출됨" 기록은 관찰로만 전하고 로컬 파일과 같은 바이트라고 단정하지 않는다.

## 5. 공지·모듈·첨부

공지:
1. 공지 목록을 열고 로딩이 끝날 때까지 기다린다("공지로드"만 보이면 미완료).
2. 최신부터 학기 시작 무렵까지 읽는다(한도 100건). 더 보기·스크롤로 남은 항목이 있으면 끝까지 본다.
3. 이 과제, 과제 공통 규칙(제출 형식, 파일 이름, 분량, 양식), 마감 변경, 정정을 다루는 공지는 **상세 화면을 열어** 전문과 첨부를 확인한다. 목록 미리보기에는 첨부가 보이지 않는다(관찰: 문제지가 첨부된 공지도 목록에는 짧은 안내 문장만 보였다). 상세가 열리지 않으면 미리보기 글을 근거로 쓰되 "상세·첨부 미확인"을 `source_limits`에 남긴다.
4. 무관한 공지는 미리보기로 판단하고 제목과 건수만 기록한다.
5. 공지의 대상("모든 섹션", "1 섹션 …")이 학생의 분반과 맞는지 본다.

모듈: 주차 모듈에 과제와 함께 붙은 머리말·안내를 확인한다.
강의계획서: 공지·과제가 가리키거나 과제 공통 규칙이 거기 있을 때 읽는다.

첨부:
- 문제지·양식처럼 요건이 걸린 첨부는 내려받아 `inspect`로 읽는다(처음 받기 전에 이름·크기를 알리고 허락).
- 문제지 안의 제출 지시(예: "9개 경우의 결과 그림을 모두 제출")를 찾아 요건으로 옮긴다. 경우마다 따로 요건을 만들면 하나만 빠져도 드러난다.
- 그림·스캔·지원하지 않는 형식이라 읽지 못한 부분에 요건이 있을 수 있으면 `source_limits`에 적는다.
- 다른 사이트로 넘어가는 링크나 로그인·권한 요청은 열지 않고 학생에게 알린다.

## 6. 판단 규칙

- **적용 대상**: 강좌·분반·대상이 맞는 지시만 쓴다. 다른 분반·다른 강좌의 공지는 제외하고, 판단할 수 없으면 확인 필요다.
- **공통 규칙**: "주간 보고서는 모두 PDF로 제출"처럼 과제 전체에 거는 규칙은, 이후 바꾸는 공지가 없으면 해당 과제들에 적용한다. 공지 제목이 특정 기간("중간고사 이전 안내" 등)을 말해도 규칙 자체가 매주 과제에 걸려 있고 바꾼 공지가 없으면 적용하되, 그 판단을 근거와 함께 밝힌다.
- **정정과 충돌**: "~로 정정합니다" 같은 명시적 정정은 같은 과제·대상일 때 이전 지시를 대체한다(둘 다 근거로 남김). 정정 표현 없이 값이 다르면 나중 것이라고 이기지 않는다 → 충돌로 보고하고 확인 필요.
- **흔한 짐작 금지**: AI 사용 고지, 표지, 서약서, 분량, 참고문헌 형식, 파일 이름 규칙 등은 해당 과제에 명시된 필수 지시가 있을 때만 요건이다. "권장합니다" 같은 안내, 일반적인 학업 윤리 문구는 요건이 아니다. "AI를 사용한 경우"처럼 조건이 붙으면 조건이 확인될 때만 점검한다.
- **메일**: 메일만으로 요건을 확정하지 않는다([gmail.md](gmail.md)).
- **날짜와 분량 표현**: 원문을 그대로 인용한다. 연도·시간대를 추정했으면 추정했다고 밝힌다. "1페이지 분량"처럼 애매한 표현은 인용과 해석을 함께 적는다.

## 7. 수집 범위와 실패

수집이 완료된 것은 과제 상세, 학기 시작까지의 공지 목록(로딩 완료), 관련 공지 전문, 요건이 걸린 첨부를 모두 읽었을 때다. 하나라도 빠지면 무엇이 빠졌는지 `source_limits`에 적는다(최대 PASS_WITH_LIMITS).

| 상황 | 할 일 |
|---|---|
| 로그인 화면·세션 만료 | 학생에게 직접 로그인 요청, 그동안의 출처는 미확인 |
| 접근 거부·권한 없음 | 그 출처를 미확인으로 두고 다른 경로로 우회하지 않음 |
| 로딩이 끝나지 않음 | 잠시 뒤 다시 읽고, 그래도 안 되면 미확인 |
| 외부 도구(iframe) 글이 안 읽힘 | 요건이 있을 수 있으면 미확인 |
| 첨부 다운로드 실패·읽기 실패 | 그 첨부에 걸린 요건은 확인 필요 또는 출처 한계 |
| 도구 출력이 잘림 | 잘린 부분은 근거로 쓰지 않음 |

## 8. 결론 직전 재확인

처음 읽은 지 10분이 넘었으면 과제 상세와 공지 목록을 다시 열어 새 공지·정정·마감 변경이 없는지 본다. 바뀌었으면 영향받는 요건을 고치고 다시 검사한다. 로컬 엔진은 네트워크에 접속하지 않으므로 출처의 최신성은 이 재확인으로만 말할 수 있다.
