# 실제 파일 내용과 제한부 통과

`review`는 호스트가 확인한 요건에 대응하는 파일을 검사한다. 과제 검색·출처 수집은 SKILL.md의 Chrome 흐름을 따르며, 이 CLI만 실행해서 eTL 최신성을 확인했다고 말하지 않는다.

## 실행과 프로필

```text
python snu_submit.py review --file submission.zip --profile profile.json --output NEWDIR --include-content
```

`--file`은 여러 번 지정할 수 있다. `--include-content`가 있으면 JSON·HTML에 추출 텍스트가 들어가므로 호스트가 내용을 직접 읽어 필수 섹션·답변 존재를 점검한다. 원본은 수정하지 않는다. 기본 출력에는 본문을 저장하지 않는다.

합성 예시:

```json
{
  "profile_version": "file-review/1",
  "requirements": [
    {
      "id": "report",
      "description": "결론을 포함한 보고서",
      "evidence": "과제 안내의 보고서와 결론 요구 인용 및 출처 URL",
      "patterns": ["submission.zip!report.docx"],
      "min_count": 1,
      "max_count": 1,
      "text_contains": ["결론"]
    }
  ],
  "source_limits": []
}
```

모든 키가 필요하다. 요구사항은 최소 1개이며 ID가 중복되면 거부한다. `patterns`는 직접 제출한 파일의 basename 또는 `외부.zip!내부/경로`에 대응한다. 대소문자는 구별하지 않으며 `*`는 디렉터리 구분자를 포함해 일치한다. 특정 파일명 지시에는 정확한 경로를 쓴다. 역할만 지정됐다면 `*.zip!database/*.cdb`처럼 관찰한 역할·확장자 기반 후보를 명시할 수 있다. `max_count: 1`은 단일 파일 요구나 초안/최종본 모호함을 드러낸다. 단순 유사 이름을 다른 역할 파일 대신 매핑하지 않는다.

`text_contains`는 명시적 필수 표지의 정확한 문자열 검사다. 정답·의미 충실도·섹션의 비어 있지 않음을 자동 보증하지 않으므로, 추출 본문과 위치를 읽어 확인한다. 그림이나 미지원 영역이 남으면 문자열 부재를 곧바로 누락으로 단정하지 않는다. 읽어서 확인한 위반은 최종 답변에서 엔진 결과보다 우선해 `수정 필요`로 보고한다.

`source_limits`에는 읽지 못한 문제 첨부, 오프라인·현재 원문 미재확인 등 실제 수집 한계를 넣는다. 다른 과제와의 혼동, 지침 충돌, 적용 여부 미해결을 단순 한계로 바꾸지 않는다. 그런 경우 과제 대응을 먼저 해결하거나 전체 `확인 필요`로 보고한다. 파일 대응·필수 조건을 근거 없이 만들지 않는다.

## 검사 범위

| 형식 | 직접 확인 | 남는 한계 |
|---|---|---|
| ZIP | 안전한 경로, CRC, 해시, 비어 있는 항목, 내부 PDF/DOCX/PPTX/XLSX/Python/텍스트 | 중첩 일반 ZIP·손상·암호화·한도 초과는 확인 필요 |
| PDF | 파서 열기, 쪽수, 텍스트와 쪽 위치 | 스캔·그림·수식의 시각적 내용 |
| Word DOCX | OOXML 구조, 문단·표·내용 위치 | 실제 쪽 배치·그림·일부 부가 파트 |
| PPTX | OOXML 구조, 슬라이드 순서·수, 슬라이드 텍스트 | 그림·차트·노트·레이아웃 |
| Excel XLSX | OOXML 구조, 시트·셀·공유 문자열·수식·저장된 계산값 | 재계산하지 않음, 차트·외부 데이터·서식 |
| PY | UTF-8 원문, 구문 오류, 코드 위치 | 실행·외부 모듈 설치·정답 검증 없음 |
| database·FIG·구형 DOC/XLS·HWP 등 | 존재, 크기, 해시, ZIP 안에서는 CRC | 전용 프로그램의 내용 확인 필요 |

ZIP은 풀지 않고 메모리에서 읽는다. 파일당 50 MiB, 제출 파일 합계 200 MiB, ZIP 1,000항목·해제 읽기 200 MiB, 텍스트 100,000자, 파서 30초 제한을 적용한다. ZIP 내부 OOXML 해제량도 바깥 ZIP과 같은 예산에 합산한다. 한도는 과제 제한이 아니라 제품 검사 범위다.

## 판정

- `PASS`: 이 프로필의 파일·텍스트 조건이 모두 확인됨. 전체 온라인 제출 준비 PASS로 말하려면 SKILL.md의 추가 출처·내용 검토 조건도 충족해야 한다.
- `PASS_WITH_LIMITS`: 알려진 필수 파일 후보가 모두 있고 비어 있지 않으며, 남은 문제가 전용 형식·그림·계산 재현 또는 명시된 출처 범위의 한계뿐임. “파일은 모두 있는 것으로 보임”과 직접 확인할 파일·내용을 함께 말한다.
- `NEEDS_CHANGES`: 요구 파일 누락, 개수 위반, 빈 필수 파일, 읽을 수 있는 필수 표지 누락, Python 구문 오류 등 관찰된 위반.
- `NEEDS_CONFIRMATION`: 파일 접근·파서 실패, 손상, 암호화, 안전하지 않은 항목, 중첩 일반 ZIP, 예산 초과, 검사 중 변경. 제한부 통과로 올리지 않는다.

파일 판정·출처 수집·제출 가능 기간·기존 서버 접수는 별도 사실이다. `PASS_WITH_LIMITS`는 “지금 제출 가능”, “모든 문제 정답”, “내용 확인 완료”를 뜻하지 않는다. 사용자가 고친 뒤에는 같은 프로필로 새 폴더에 다시 검사하고 각 파일 SHA-256과 항목 결과를 비교한다.
